# 양수 요소 3개 진입 제한

## 적용 규칙
- 기존 총점·점수차·재진입 제한을 모두 유지하고, 해당 방향의 양수 요소가 3개 이상이어야 신규 진입합니다.
- 즉시 방향 전환도 새 방향에 양수 요소 3개 이상이 필요합니다. 부족하면 전환 목적의 기존 포지션 청산도 하지 않습니다.
- 손절·수익보호·트레일링은 이 제한과 별개로 계속 작동합니다.
- 실거래·드라이런·페이퍼에 동일하게 적용합니다. 비활성화된 추가 진입 기능은 변경하지 않았습니다.

## 개수에 포함하는 요소
1. 장기 가격 위치
2. 몸통
3. 거래량
4. 추세 지속성
5. RANGE 최종 순점수
6. 청산 본점수

각 요소가 해당 방향에 0보다 큰 점수를 줄 때 1개입니다. 6점을 줘도 1개입니다.
RANGE의 위치·돌파·가장자리 감점은 합친 최종 순점수가 양수일 때만 1개로 셉니다.
ATR 활동 방향 가점과 청산 활동 보너스는 요소 개수에서 제외합니다. 총점에서는 기존처럼 유지합니다.
몸통·거래량·추세 등은 상관관계가 있으므로 3개가 독립적인 증거 3개라는 뜻은 아닙니다.
구성요소가 누락되거나 유효한 숫자가 아니면 양수 요소로 세지 않습니다.

## 기록과 예측
- ATR 가산점은 최대 3점 그대로입니다. 원래 0~6점은 기존 indicators_json의 atr.raw_score에 저장됩니다.
- indicators_json.entry_eligibility에 방향별 개수·최소 개수·요소 목록·허용 여부가 저장됩니다.
- strategy_config_json에는 entry_min_positive_components=3이 추가되어 이전 기록과 구분할 수 있습니다.
- 점수 엔진의 기존 총점과 후보 신호는 유지합니다. 후보 신호가 있어도 주문은 새 필터로 제한될 수 있습니다.
- 기존 예측 계산과 미래 진입조건 라벨은 수정하지 않았습니다. 예측의 진입조건 확률을 새 주문 제한까지 반영한 실제 주문 확률로 해석하면 안 됩니다.
- DB 스키마 변경이나 추가 Binance 호출은 없습니다.

## 검증 및 배포
전체 unittest 103개 통과. 실제 주문과 Telegram 발송 없이 모의 클라이언트로 검증했습니다.
GCP에는 자동 반영되지 않습니다. GitHub 반영 후 GCP에서 git pull하고 기존 봇을 종료·재시작해야 적용됩니다.
새 조건은 손실 제거 또는 수익 개선을 보장하지 않습니다. 적용 이후 성과는 별도로 검증해야 합니다.
