# 작은 추가분 다운로드

전체 DB는 GCP에 계속 보관합니다. 이 도구는 매매, 예측 계산, Binance 호출을 변경하지 않습니다.
전체 DB를 먼저 복사하지 않고 읽기 전용 조회로 별도의 작은 DB를 만든 뒤 ZIP으로 압축합니다.
DB와 ZIP 사이의 임시 파일은 완료 후 삭제됩니다. 이 ZIP만으로 과거 전체 분석이 되는 것은 아닙니다.

## 처음 한 번: GCP에서 만들기

로컬 변경을 GitHub에 올리고 GCP에서 git pull한 다음 실행합니다.
아래 시각은 사용자가 이미 받은 9월 20일 백업의 마지막 시장 기록입니다.

```bash
cd ~/test-bot/python_bot/market-state-engine
python3 -m market_state_engine.data_transfer export --since 2026-09-20T04:34:11.753087+00:00
```

DOWNLOAD 뒤에 나오는 ZIP 경로를 GCP의 파일 다운로드에 입력합니다.
다운로드한 ZIP이 정상인지 확인하고 로컬의 기존 전체 DB와 함께 보관합니다.
이미 받은 최신 전체 DB가 다른 파일이면 --since도 그 DB의 마지막 timestamp로 지정해야 합니다.

## 다운로드를 끝낸 뒤 확인

아래 명령은 사용자가 다운로드를 완료했다고 확인하는 동작입니다.
실제로 다운로드를 확인하기 전에는 실행하지 마세요.

```bash
python3 -m market_state_engine.data_transfer confirm --downloaded --delete-export
```

다음 시작 시각을 저장하고 방금 확인한 GCP의 ZIP만 삭제합니다.
--delete-export를 빼면 해당 ZIP을 서버에 남깁니다.
원본 DB, 기존 전체 백업, 다른 ZIP이나 사용자 PC의 파일은 삭제하지 않습니다.

## 다음부터

```bash
python3 -m market_state_engine.data_transfer export
```

날짜를 다시 입력하지 않습니다. 아직 다운로드 확인을 하지 않았으면 이전 ZIP을 그대로
안내하고 새 파일을 반복 생성하지 않습니다. 다운로드 실패 시 동일 명령으로 경로를 다시 확인합니다.
다음 다운로드를 위해서는 이전 다운로드 확인 단계까지 완료해야 합니다.

work/exports/research_export_cursor.json에는 마지막 확인 시각과 진행 중인 ZIP 정보가 저장됩니다.
이 파일을 지우면 다음 시작 시각을 잊습니다. 원본 DB 경로 하나마다 별도 exports 디렉터리를 사용하세요.
잠금 파일 research_export.lock은 동시 실행을 막습니다. 프로세스 강제 종료 뒤 잠금이 남았다면
다른 내보내기/확인 작업이 실행 중인지 먼저 확인하고 복구해야 합니다. 자동으로 잠금을 지우지 않습니다.

## 포함되는 데이터

- market_state: 마지막 확인 시각보다 하루 전부터의 전체 시장 행.
- market_state_labels: 모든 시점의 future_* 및 return_* 라벨 열과 기본 키만 담은 작은 표.
  과거 행에 updated_at이 없으므로 하루보다 늦게 붙는 정답도 놓치지 않도록 이 열들을 재전송합니다.
- prediction_forecast, prediction_digest: 과거 실제 결과 갱신을 포함한 전체 예측/보고 기록.
- manifest.json: 시작/종료 시각, 행 수, 연결할 이전 추가분 ID, 데이터 체크섬.

대용량인 과거 시장 행의 지표/JSON 전체는 반복 전송하지 않습니다. 라벨과 예측/보고 기록은
재전송하므로 전송량이 새 시장 행 수에만 비례하는 순수 변경 추적 방식은 아닙니다.
앞으로 예측 기록이 많이 쌓이면 이 부분에도 변경 추적이 필요할 수 있습니다.
과거 원본 시장 행은 변경되지 않고 미래 라벨만 갱신된다는 현재 봇의 구조를 전제로 합니다.
임의의 과거 가격 수정, 삭제, 다른 테이블까지 복제하는 일반 DB 동기화 도구는 아닙니다.

## PC에서 합치기

기존 전체 DB와 새 ZIP을 같은 코드가 있는 컴퓨터에서 합칠 수 있습니다.
기존 DB를 덮어쓰지 않고 지정한 새 이름으로 합쳐진 DB를 만듭니다.

```bash
python -m market_state_engine.data_transfer merge --base "기존전체.db" --archive "받은추가분.zip" --output "합친전체.db"
```

다음 추가분을 합칠 때는 직전 합친전체.db를 --base로 사용합니다.
누락 구간이 생기는 오래된 기준 DB, 이미 합친 ZIP, 순서가 맞지 않는 추가분,
이미 존재하는 출력 파일은 거부합니다. 중복 시각은 기본 키로 갱신하며 이전 기록은 지우지 않습니다.
합치기는 원본 보존을 위해 PC에 전체 DB 복사본을 하나 만드는 작업입니다. PC 디스크 여유가 필요합니다.
GCP의 실행 중인 원본 DB에 합친 파일을 덮어쓰지 마세요.

DB가 오래될수록 서버 원본 자체가 커지는 문제는 별개입니다. 보존 기간 변경이나 원본 삭제는
이번 도구에서 수행하지 않습니다. exports의 기존 전체 백업도 자동 삭제하지 않습니다.
